# Connection Odds

How often is a US domestic connection missed, and how long a layover does a 95% chance take? This project pairs every arrival and departure at the 30 busiest US airports from the BTS on-time data, September 2023 to August 2026, scores each pair against what actually happened, and puts the result in a lookup tool that runs in the browser.

[Lookup tool](https://lyhjeremy.github.io/connection-odds/) · [Write-up](https://lyhjeremy.github.io/connection-odds/overview/)

Design and copy follow [these standards](https://github.com/lyhjeremy/lyhjeremy/blob/main/DESIGN_STANDARDS.md).

## Results

- Across the 30 hubs, {{all45}}% of 45-minute connections were missed, {{all90}}% of 90-minute ones and {{all30}}% of 30-minute ones. A miss counts a cancelled or diverted inbound, a cancelled outbound, or an inbound that reached the gate less than W + D = 30 minutes before the outbound pushed back.
- At {{topHubName}} ({{topHub}}), the busiest hub, a 45-minute connection was missed {{topHub45}}% of the time and a 95% chance took {{topHub95}} minutes. At 45 minutes the worst hub was {{worst45name}} ({{worst45}}%) and the best {{best45name}} ({{best45}}%).
- {{allFloor}}% of pairs failed on a cancellation or diversion, which no layover fixes. Counting those, {{hubsReach95}} of {{hubsTotal}} hubs reach 95% within 180 minutes. If both flights operate, 95% takes {{flown95min}} ({{flown95minHub}}) to {{flown95max}} ({{flown95maxHub}}) minutes, and {{flownMedian8}} minutes for an 8 am arrival against {{flownMedian19}} for a 7 pm one at the median hub.
- Reading only the inbound delay overstated the miss rate at 45 minutes by {{sc45gap}} points ({{sc45naive}}% against {{sc45paired}}%). When the inbound was 30 or more minutes late, the outbound left 15 or more minutes late {{depLateGiven}}% of the time, against {{depLateBase}}% overall. From about {{scCross}} minutes the shortcut understates instead, because it ignores outbound cancellations.
- Tested on March to August 2026 after fitting on the 30 months before, the logistic model had a calibration error of {{modelEce}} points (Brier {{modelBrier}}), the cell-average lookup {{lookupEce}} ({{lookupBrier}}) and the inbound-only shortcut {{naiveEce}} ({{naiveBrier}}). The tool ships the model, refitted on all 36 months.
- Calendar 2019 looked much the same: {{y2019_45}}% missed at 45 minutes.

Connections are constructed from flight pairs, not real bookings. Limits are listed in the write-up.

## Data

US Bureau of Transportation Statistics, Marketing Carrier On-Time Performance (Beginning January 2018), monthly zips from [transtats.bts.gov/PREZIP](https://transtats.bts.gov/PREZIP/): {{flights}} flights from {{firstDate}} to {{lastDate}}, plus calendar 2019. Public domain. The marketing-carrier table is used because a traveler books the marketing airline: a SkyWest-operated United Express leg is United here. Data decisions are in [`docs/decisions.md`](docs/decisions.md).

## How to run

```bash
python -m venv ~/venvs/connection-odds && ~/venvs/connection-odds/bin/pip install -r requirements.txt
export CONN_CACHE=~/data-cache/connection-odds   # raw data stays outside the repo
python scripts/fetch_bts.py        # 48 monthly zips (about 38 MB each) to parquet in the cache; resumes
python -m pytest -q tests          # pair builder tests
python scripts/build_pairs.py      # hubs, {{pairsM}} million sampled pairs in the cache
python scripts/analyze.py          # tables/, results/summary.json
python scripts/export_web.py       # assets/tool.json ({{toolKB}} KB)
python scripts/make_figures.py     # figures/
python scripts/export_numbers.py   # site/numbers.json
python scripts/build_site.py       # index.html, README.md, write-up fragment
```

`scripts/run_all.sh` runs everything after the fetch. No number in the README, the tool page or the write-up is typed by hand: `export_numbers.py` writes them and `build_site.py` fills the templates in `site/`.
